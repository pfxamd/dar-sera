# Implementation validation

## Completed checks

- Astro/TypeScript diagnostics: no errors or warnings.
- Static production build: 11 main routes plus a custom 404 page.
- Unit tests: 2 passed, covering date-only nights, leap years, year boundaries, invalid dates, past arrivals, same-day departure and guest limits.
- Browser tests: 5 passed in Chromium.
- Main route coverage: 11 routes at 390, 768, 1440 and 1920 px.
- All page images explicitly loaded during browser checks; no broken images, horizontal overflow or JavaScript runtime errors.
- House explorer: level switching, room selection, room links.
- Gallery: keyboard navigation, Escape dismissal and focus return.
- Mobile navigation: dialog dismissal and focus return.
- Booking: validation, room preselection, totals, editing, field preservation, safe rendering of literal HTML input, completion and clipboard fallback.
- No outgoing form POSTs and no local/session storage writes during tested booking flow. Contact values clear on refresh.
- Essential homepage and room content checked with JavaScript disabled.
- Production dependency audit: 0 reported vulnerabilities at validation time.
- Image manifest: 28 files with distinct SHA-256 hashes; supplied resolutions preserved.

## Visual review

Homepage captures were reviewed at desktop and mobile widths. Room and booking captures were also inspected. The source screenshots are generated by `npm run test:e2e`; representative review images are kept alongside this document.

## Deliberate boundaries

- No live deployment has been performed.
- No real reservation, payment, email service or availability source is connected.
- Property and destination images are generated assets supplied by the user; destination illustrations are labelled.
- The house plan is schematic, not a measured architectural plan or a guarantee of exact spatial reconstruction across generated images.
- Supplied WebP sources are smaller than the original brief’s requested master sizes. No artificial upscaling was applied.
- Browser checks were performed in Chromium, not a claim of physical-device or every-browser certification.
- No field Core Web Vitals measurements or production traffic data are available before deployment.

## GitHub Pages preparation

The production base is `/dar-sera/`. Internal links, favicon and generated assets are base-aware. The built HTML was checked for root-relative references escaping that base. Deployment uses one build-and-publish job, with image-cache reuse and no browser installation in CI. Enabling GitHub Actions as the repository Pages source is an administrative prerequisite.
